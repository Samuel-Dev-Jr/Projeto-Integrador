Segurança

Seu código é lido, nunca guardado

Uma ferramenta de segurança precisa dar o exemplo. Estas são as regras que o SpyCode segue com o seu repositório, em todas as partes do sistema.

O caminho do seu código

Do GitHub ao laudo, sem o código ficar com a gente

  1. Você autoriza

    Entra com o GitHub e escolhe o repositório. O SpyCode pede só permissão de leitura.

  2. Uma cópia é baixada

    O código vai para uma pasta temporária, separada para cada análise.

  3. Os motores leem

    O código é lido como texto. Nenhuma linha dele é executada.

  4. Fica só o laudo

    A pasta é apagada no fim, mesmo quando a análise dá erro.

As regras

O que vale em todas as análises

Só leitura

O SpyCode pede ao GitHub a menor permissão possível.

Nada é executado

A análise só lê os arquivos. O seu código nunca roda no servidor.

Cópia apagada

Depois da análise, o banco guarda só o laudo.

Segredo mascarado

Na tela, no banco e no log. Você vê sk_live_••••4f2a, nunca a chave inteira.

Acesso protegido

A autorização do seu GitHub fica criptografada no banco.

Atalhos ignorados

Links simbólicos do repositório são pulados, porque podem apontar para fora da pasta temporária.

Limites

Tamanho máximo de repositório, tempo máximo por análise e limite de pedidos.

Testado em casa

O repositório do próprio SpyCode passa pelo scanner antes de cada entrega.

Seus dados

O que fica guardado e o que não fica

Guardamos

  • Quem você é: o seu usuário do GitHub
  • Os repositórios que você conectou
  • O laudo de cada análise: achados, nota e data
  • O que você marcou como falso positivo

Nunca guardamos

  • O seu código
  • Segredos inteiros
  • Senhas em texto puro

Só o dono escaneia

O SpyCode analisa apenas os repositórios que a própria pessoa conecta, pela conta dela do GitHub, e o resultado aparece só para ela. Não dá para escanear o projeto de outra pessoa.

O SpyCode está em construção. Estas regras valem desde a primeira versão e são conferidas antes de cada entrega.
